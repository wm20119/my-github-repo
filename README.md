# 🏠 汪淼的个人资产库

> 个人 GitHub 的核心作用，不只是"存代码"，而是把代码、配置、文档、自动化脚本和项目历史，变成一个**可版本控制、可追溯、可协作、可自动化**的长期资产库。

## 📁 目录结构

| 目录 | 用途 | 适合的内容 |
|------|------|-----------|
| **scripts/** | 日常脚本 | PowerShell、Python、Shell、批处理 |
| **projects/** | 完整项目 | A股模拟系统、FamilyTimeLock 等 |
| **docker/** | Docker 配置 | docker-compose、Dockerfile、配置模板 |
| **configs/** | 配置文件 | 网络配置、NAS配置、系统配置 |
| **docs/** | 文档资料 | 设计文档、测试记录、操作手册 |
| **android/** | Android 工具 | APK、工具脚本、配置 |
| **data/** | 数据整理 | CSV、JSON、数据库备份 |
| **automation/** | 自动化脚本 | 定时任务、CI/CD、自动部署 |
| **templates/** | 配置模板 | 常用配置模板、脚本模板 |

## 🎯 核心价值

- **版本控制** — 每次修改都有记录，可以回退
- **异地备份** — 本地/NAS坏了仍有远端副本
- **协作平台** — Issue、PR、分支管理
- **自动化** — GitHub Actions 自动测试、构建、发布

## 🚀 快速开始

```bash
# 克隆到本地
git clone https://github.com/wm20119/my-github-repo.git

# 进入目录
cd my-github-repo
```

## 📝 使用规范

1. **文件命名**：英文小写+下划线，如 `stock_screener.py`
2. **目录分类**：按类型放对应目录，别乱扔
3. **README**：每个重要项目单独写 README
4. **版本号**：重要脚本标注版本 `v1.0`、`v2.0`
